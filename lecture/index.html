1 密码算法基础与后量子密码

1.1 密码学总览

现代密码学按“密钥是否相同”与“有无密钥”分为三大类。本章梳理每一类的代表算法、特点与安全现状：

类别代表算法提供的安全属性
对称密码AES、SM4、3DES、ZUC、ChaCha20机密性（加解密）；配合 MAC/GCM 提供完整性
非对称密码RSA、ECC（ECDSA/ECDH）、SM2、SM9、DH密钥交换、数字签名（认证 + 不可否认）
杂凑函数SHA-2、SHA-3、SM3、MD5（已破）、SHA-1（已破）完整性、数据指纹；构成签名/MAC/度量 的基础

安全属性速记：机密性（加密）、完整性（哈希/MAC）、认证（MAC/签名/证书）、不可否认性（数字签名，只有签名能提供）。

1.2 对称密码算法

1.2.1 特点

  • 加解密使用同一密钥，加解密算法（通常）相同或可互推。
  • 速度快（比非对称快约 2–3 个数量级），适合加密大批量数据。
  • 密钥分发是难点：𝑛 个人两两保密通信需要 𝑛(𝑛−1)2 个密钥；通常用非对称算法或密钥协商来分发对称会话密钥（混合加密 / 数字信封）。
  • 密钥长度短即可达高安全强度：128 位即当前公认安全，256 位可抗量子（Grover）。

1.2.2 分组密码

算法密钥/分组长度结构现状与备注
DES56 / 64 bitFeistel，16 轮已不安全：56 位密钥可暴力破解（1998 年 EFF “Deep Crack”）
3DES112 有效 / 64 bitDES 三重迭代安全性不足：SWEET32（64 位分组生日攻击）；NIST SP 800-131A 已于 2023 年后禁止用于加密
AES128/192/256 / 128 bitSPN，10/12/14 轮当前国际主流；无实用攻击（最好攻击约 2126，Biclique）；128 位在量子模型下仅相当于 64 位强度
SM1128 / 128 bit非公开国密分组算法，算法不公开、以安全芯片形式提供
SM4128 / 128 bitFeistel，32 轮国密分组密码，GB/T 32907-2016；无线局域网 WAPI 起源，现广泛用于商用密码
SM7128 / 128 bit非公开用于非接触 IC 卡（门禁、票务）

1.2.3 工作模式（分组密码如何加密任意长度数据）

模式机制要点/风险
ECB各分组独立加密相同明文 → 相同密文，泄漏数据模式；禁止用于实际数据
CBC当前分组先与上一密文块异或再加密，需 IV串行；存在 Padding Oracle 攻击；IV 需不可预测
CTR加密计数器生成密钥流再异或流式、可并行、可随机访问；nonce 重用即致命
GCMCTR + GHASH 认证AEAD（认证加密）：同时提供机密性与完整性；nonce 重用会泄漏认证密钥

流密码代表：RC4（已破，存在统计偏差，RFC 7465 禁止用于 TLS）、ZUC/祖冲之（国密流密码，3GPP LTE 标准 128-EEA3/128-EIA3）、ChaCha20-Poly1305（TLS 常用）；资源受限设备另有 NIST 2023 年选定的轻量级密码 Ascon（SP 800-232）。

1.3 非对称密码算法

1.3.1 特点与代表算法

算法数学难题典型用途
RSA大整数分解（GNFS）加密（OAEP 填充）、签名（PSS）、密钥传输
DH / DSA模乘离散对数密钥协商 / 签名；1024 位已不安全（Logjam）

◆ 要点 “教科书式 RSA”（无填充）是确定性的且易被选择密文攻击，实际必须使用填充方案：加密用 OAEP，签名用 PSS。ECDSA 的随机数 k 必须一次性且保密：k 一旦重用或泄漏，私钥即可恢复，PS3 被破解正是源于固定 k。

1.4 杂凑函数、MAC 与数字签名

算法输出长度现状
MD5128 bit已破：王小云等 2004 年提出碰撞方法；Flame 恶意软件利用 chosen-prefix 碰撞伪造微软签名（2012）
SHA-1160 bit已破：SHAttered 实际碰撞（2017）；“Shambles” chosen-prefix 碰撞（2020）；主流浏览器/CA 已弃用
SHA-2（224/256/384/512）224–512 bit当前主流，安全
SHA-3（Keccak）可变与 SHA-2 结构完全不同（海绵结构），备份路线
SM3256 bit国密杂凑，GB/T 32905-2016，安全强度与 SHA-256 相当
  • MAC（消息认证码）：哈希/MAC 密钥参与运算，提供完整性 + 认证，但无不可否认性（双方同钥）。代表：HMAC（哈希 + 密钥）、CMAC（分组密码构造）、GMAC。
  • 数字签名：先哈希后用私钥签名，任何人都可用公钥验证，提供完整性 + 认证 + 不可否认性。代表：RSA-PSS、ECDSA、EdDSA、SM2 签名。
  • PKI/证书：X.509 证书将公钥与身份绑定，CA 签发，证书链逐级验证，根信任锚为根 CA 证书。

◆ 要点 区分三种“不安全”：被实际攻破（DES、RC4、MD5、SHA-1）→ 必须换；密钥强度不足（RSA-1024）→ 加长；使用方式不当（ECB、IV 重用、教科书式 RSA、ECDSA 的 k 重用）→ 正确用法下算法本身仍安全。另外，HMAC-MD5 因密钥参与内层构造，碰撞攻击难以直接利用，但规范上已不建议。

1.5.1 量子计算的威胁

  • Shor 算法：多项式时间解决大整数分解与离散对数，因此 RSA、DH、DSA、ECC（含 SM2、SM9）在足够规模的通用量子计算机面前全部失效。
  • Grover 算法：对搜索类问题只有平方加速，对称密码的有效强度因此减半：AES-128 约剩 ≈264（不足），AES-256 约剩 ≈2128（仍然安全）；哈希原像搜索同理减半，故 SHA-256/SM3 仍可使用。
  • “先截获、后解密”（Harvest Now, Decrypt Later）：敌手现在记录密文，等量子计算机成熟后回溯解密，因此长周期保密数据需要现在就迁移后量子密码。
  • Mosca 不等式：若“数据需要保密的时间 x”+“迁移所需时间 y”大于“量子计算机到来时间 z”，即 𝑥+𝑦>𝑧，就必须现在开始迁移。

1.6.3 迁移趋势

  • NIST 迁移路线：RSA-2048 与 ECC P-256 等在 2030 年弃用、2035 年禁用；美国 CNSA 2.0 已要求国家安全系统限期切换（强调 AES-256、SHA-384、ML-KEM-1024）。
  • 混合模式（Hybrid）：经典 + 后量子并联（如 TLS 1.3 的 X25519MLKEM768），任何一边被破仍安全；Chrome/Cloudflare 等已默认启用。
  • 密码敏捷性（Crypto-Agility）：算法可配置、可替换的架构能力，是后量子迁移的工程前提。
  • 中国进展：SM2/SM3/SM4 属经典算法，公钥部分同样受量子威胁。2019 年中国密码学会发起全国密码算法设计竞赛；2025 年 2 月商用密码标准研究院启动新一代商用密码算法征集（公钥/杂凑/分组，明确要求兼具传统安全与抗量子安全）；国家密码管理局第 46 号公告提出抗量子迁移总体技术架构、第 55 号公告给出迁移敏捷性评价指标；金融行业已发布《银行业抗量子计算密码迁移管理指南》。
◆ 厂商实践与拓展 华为开源的高性能密码库 openHiTLS 同时覆盖国际算法、国密与 NIST 首批后量子算法，适合用来研究工程实现。后量子算法的密钥与签名达到 KB 量级、运算以多项式乘法为主，对芯片的 NVM 容量和总线带宽都提出了新要求，硬件上通常用数论变换（NTT）加速器实现格密码运算。这类加速器是芯片设计与密码工程的交叉方向。

1.7 同态加密与全同态密码（FHE）

【同态加密 Homomorphic Encryption】 允许直接在密文上计算、且解密结果与在明文上计算一致的加密体制。按能力分级：PHE 部分同态（单一运算）→ SWHE 层次同态（有限乘法深度）→ FHE 全同态（任意电路）。
  • 部分同态经典方案：RSA（乘法同态）、ElGamal（乘法同态）、Paillier（加法同态），已进入 ISO/IEC 18033-6；用于电子投票聚合、安全求和等。
  • FHE 里程碑：Gentry（2009）基于理想格给出首个 FHE 构造，核心思想 bootstrapping（自举）——在密文域内执行解密电路来“刷新”累积噪声、恢复同态能力。此后主流方案均基于格（与 PQC 同源，天然抗量子）。
  • 主流方案族（记“族对应”）：
方案族算术类型特点与适用
BGV / BFV精确整数/模运算向量精确计算：数据库密文查询、整数统计；深度大时需自举
CKKS近似实/复数向量AI 推理首选：天然匹配神经网络运算，精度损失可控
TFHE / CGGI布尔门/查找表自举最快（毫秒级、可逐门自举），适合任意深布尔电路
  • 性能开销与硬件加速：同态运算比明文慢 3–6 个数量级，密文膨胀严重，实用化必须依靠硬件加速，这正是“密码库软硬件协同”与“AI 算力安全”的交汇点。代表加速器与项目有 Microsoft HEAX、SRI F1/CraterLake（DARPA DPRIVE 计划）、MIT ARK，国内蚂蚁集团等也发布了 FHE 加速方案；加速的核心是 NTT 多项式乘法引擎（与格密码 PQC 加速同源）、大整数运算与高带宽内存。
  • 标准化：HomomorphicEncryption.org 社区标准（安全参数选取）；ISO/IEC 18033-6 收录部分同态方案。

◆ 要点 FHE 的要点可以归纳为三句：它是格上构造的、能在密文上计算任意函数的加密体制，因此抗量子；方案族按算术类型分工，CKKS 适合 AI 推理，TFHE 适合布尔电路，BGV/BFV 适合精确整数；由于开销极大，NTT 加速器成了硬件工程师最相关的切入点。

1.8 密码算法的实现

同样的算法，实现不当会完全失去安全性。实现层面分软件、硬件与工程保障三条线：

1.8.1 软件实现要点

  • 恒定时间（Constant-time）原则：执行时间、内存访问模式不得依赖秘密数据（防时序侧信道）；避免以秘密值为索引的查表（cache 计时泄漏）与秘密依赖分支。
  • 侧信道对抗：RSA 使用指数盲化/消息盲化；ECDSA 采用确定性 nonce（RFC 6979）或nonce 重用检测。
  • 密钥生命周期管理：密钥用后清零（防止残留内存泄漏）、禁止进入交换分区/核心转储、限定拷贝。
  • 使用经过审计的成熟库（OpenSSL/BoringSSL/mbedTLS/openHiTLS），禁止自研密码算法。

1.8.2 硬件实现要点

  • 密码协处理器/安全岛：AES-NI、鲲鹏 KAE 等 CPU 指令/引擎级加速；密钥只在专用寄存器/安全存储中出现。
  • 真随机数发生器 TRNG：物理熵源（振荡器抖动、混沌电路、SRAM 上电状态）+ 数字化 + 在线健康测试（NIST SP 800-90B/C 框架：熵源评估 + DRBG 构造）。随机数是整个密码体系的根基。
  • 防物理攻击设计：掩码、隐藏、传感器（详见第 2 章）——“密码算法的实现”与物理防护在安全芯片中是一体设计。

1.8.3 密码库的软硬件协同设计

  • 硬件指令/引擎层：x86 的 AES-NI、VAES、SHA-NI；ARMv8 Crypto Extensions（AESE/AESD/PMULL）；鲲鹏 KAE 引擎；RISC-V Zk 标量加密扩展（Zkne/Zknd = AES 轮函数、Zknh = SHA-2，Zksed/Zksh = SM4/SM3——国密指令已进 RISC-V 标准）；向量扩展 NEON/SVE/RVV 承担批量运算；PQC/FHE 用 NTT 加速器。
  • 库架构层：算法与实现解耦——OpenSSL 3.x Provider（旧 Engine）机制、PKCS11、国密 SDF 接口（GM/T 0018）；硬件不可用时回退软件实现，降级路径也必须恒定时间。

  • 协同设计要点：

    • API 稳定性与语义：异步接口、上下文/会话管理、密钥句柄不外泄；
    • 调用开销分界：小数据走指令、大数据走引擎/加速器，零拷贝 + 批量提交，避免数据搬运抵消加速收益；
    • 硬件实现同样需要审计（掩码/查表实现可能泄漏）；
    • 软硬版本一致性：KAT 正确性 + 性能基准纳入 CI 回归。
  • 代表工程：openHiTLS（华为开源，算法-硬件自适应调度）、OpenSSL Provider、BoringSSL（恒定时间优先）。

2.1 攻击者模型与攻击分类

2.4.2 经典攻击（理解“故障如何变现”）

  • Bellcore 攻击（Boneh-DeMillo-Lipton，1997）：对 RSA-CRT 签名注入一次故障得到错误签名 𝑠，与正确签名 𝑠′ 满足 gcd(𝑠−𝑠′,𝑁)=𝑝，一次故障即可分解 N 得到私钥。RSA-CRT 签名后必须加验签检查。
  • AES 差分故障分析 DFA：在最后几轮注入单字节故障，通过正确/错误密文差分即可在少量故障内恢复轮密钥。
  • 指令跳过：毛刺打在“比较+跳转”上即可绕过 PIN 校验、启动验签、次数计数器——实际攻击中最常用。
  • Safe-Error 攻击：观察“该操作出错与否”对行为的影响来推断秘密比特。
  • 冷启动攻击：断电后即刻冷却 DRAM，读出残留数据提取密钥（Halderman 等，2008）。
  • 实际场景：游戏机破解（PS3 glitch、Switch Fusée Gelée）、加密硬件钱包电压毛刺攻击（公开演示多次成功）、汽车 ECU/TPMS 克隆、智能卡盗版。

3.1 硬件可信根（Hardware Root of Trust）

【硬件可信根】 系统中无条件被信任的最低层硬件基元：它的正确性不依赖任何其他软件/硬件假设，是整条信任链的起点。核心特征：不可篡改、最小 TCB、可验证。

3.2 安全启动、可信启动与度量

3.2.1 安全启动（Secure Boot）

  • 原理：逐级验签、验不过就不执行。信任链：Boot ROM（不可变代码）验证并启动 BL1，BL1 验证 BL2，逐级向下直到 OS 内核与系统服务，每一级只运行通过了签名校验的下一级。
  • 信任锚：ROM 中代码 + OTP 中的公钥哈希（固件签名公钥的哈希，防直接替换公钥）。
  • 配套：防回滚（版本单调递增，用 OTP 计数/熔丝记录最低可接受版本）；失败处理（停机/进入恢复模式）。
  • 目标：完整性——只有授权（签名）的代码能运行。

3.2.2 可信启动（Measured Boot / 度量启动）

  • 原理：逐级度量、只记录不拦截。每级启动前计算下一级的哈希并“扩展”进可信模块的 PCR：PCR_new = Hash(PCR_old ‖ 度量值)（extend 运算，不可伪造历史）。
  • 度量链起点称 CRTM（Core Root of Trust Measurement，如 BIOS 代码段）。
  • 事后可用可信模块对 PCR 状态做签名引用（Quote），供远程验证方比对白名单——远程证明（Remote Attestation）：用 nonce 防重放，AK/ attestation 密钥签名。
  • 目标：可证明性——能向第三方证明“系统是以什么软件状态启动的”。

3.3 TPM 与可信计算

【TPM（Trusted Platform Module）可信平台模块】 TCG 标准化的独立密码模块（ISO/IEC 11889，当前为 TPM 2.0），提供 PCR 度量、密钥分层管理、签名/加密、随机数、密封存储、远程证明。
  • 三类根密钥：EK 背书密钥（设备唯一身份，出厂配证书）、SRK 存储根密钥、AK/Attestation 证明密钥（做 Quote 签名，保护隐私）。
  • 密封（Sealing）：把数据加密绑定到指定 PCR 状态——系统配置“健康”时才能解密（如 BitLocker）。
  • PCR 特性：只能 extend、重启清零、不可篡改历史。
  • 固件 TPM（fTPM）：跑在 TEE 里的软件 TPM（Intel PTT、AMD fTPM），省掉独立芯片但强度依赖 TEE。
  • 中国可信计算：TCM 可信密码模块（采用 SM2/SM3/SM4 国密算法，GM/T 0012 接口规范）与TPCM 可信平台控制模块（可信计算 3.0″双体系、主动度量“架构），与 TPM 并列。

3.4 HSM、SSM 与密码模块安全等级

【HSM（Hardware Security Module）硬件安全模块】 专用的抗物理攻击密码设备：密钥全生命周期（生成/存储/使用/备份/销毁）都在设备内部，明文密钥永不出模块。形态：PCIe 密码卡、网络型 HSM、USB、云 HSM。
  • 功能：密钥管理、高速加解密、签名验签、真随机数；接口：PKCS11、CNG/JCA；国密体系用 SDF 接口（GM/T 0018）。
  • 典型应用：CA 根密钥保护、支付系统 PIN/密钥体系（金融数据密码机）、代码签名、区块链密钥托管。
  • FIPS 140-3 安全等级：
等级要求
Level 1单芯片级，无物理防护要求（软件密码库也可）
Level 2防篡改指示：涂层/封条/锁；角色认证

4 可信执行环境 TEE 与机密计算

4.1 TEE 基本概念

【TEE（Trusted Execution Environment）可信执行环境】 与富执行环境（REE，普通 OS/应用）硬件级隔离的执行环境，为敏感代码/数据提供隔离执行、完整性与机密性保护。GlobalPlatform 定义了 TEE 系统架构与 Internal API 标准。
  • 基本元素：TA（Trusted Application 可信应用）运行在 TEE 内；CA（Client Application）运行在 REE，通过驱动/API 发起请求；两者以共享内存 + 消息交互。
  • TEE 能防御：恶意/被攻陷的 REE 内核与超级应用；TEE 不能充分防御：物理攻击与微架构侧信道（后面详述）。
  • TEE vs SE：TEE 算力强、物理防护弱；SE 物理防护最强、算力弱。手机里常见“inSE 管 root of key + TEE 做密钥运算”的组合。

4.2 ARM TrustZone

  • 把整个 SoC 划分为安全世界（Secure）与普通世界（Non-secure）：NS 位贯穿处理器模式、AXI 总线、内存控制器与外设。
  • 内存：TZASC（安全内存控制器，划定安全 DRAM 区间）；外设：TZPC 按安全/非安全配置；中断：GIC 按组路由。
  • 切换：普通世界执行 SMC 指令陷入 Secure Monitor（EL3，最高异常级），由它保存/恢复上下文并切世界。EL3 固件事实标准是 ARM Trusted Firmware（TF-A）。
  • 软件栈：S-EL1 跑 TEE 操作系统（OP-TEE、QSEE、Kinibi、Trusty、华为 iTrustee…），S-EL0 跑 TA；ARMv8.4 起 S-EL2 支持安全世界虚拟化（Hafnium），是“机密虚机”的底座。

4.3 Intel SGX

  • 思路：不隔离“世界”，而是在普通 OS 内为单个进程划出飞地（Enclave）；信任边界缩到 CPU 芯片——OS/驱动/BIOS/SMM 全部不可信。
  • 机制：EPC 加密内存页（MEE 内存加密引擎）；Sealing（密钥绑定到 CPU/飞地，数据落盘可复原）；远程证明：EPID（早期）→ DCAP/ECDSA（现行）。
  • 现状：Intel 已从客户端 CPU（11 代起）移除 SGX，服务器（Xeon）保留并被 TDX 接棒。
  • 安全史（针对 SGX 的知名攻击多属此类）：Foreshadow/L1TF（2018，L1 缓存读出飞地数据）、Plundervolt（2019，软件控制电压扰动飞地计算）、SGAxe（2020，MDS 抽取密钥并伪造证明）、ÆPIC Leak（2022，架构级泄漏）、Downfall（2023，gather 指令跨飞地泄漏）。

4.5 其他机密计算方案

  • Intel TDX：以虚机为粒度的 Trust Domain；T-Module 运行在 SEAM 模式，托管 TD 生命周期；与 SEV-SNP 同为“机密虚机（CVM）”主流。
  • NVIDIA Confidential Computing（H100+）：GPU TEE，保护大模型训练/推理数据的“可用不可见”。
  • RISC-V：Keystone（开源 Enclave 框架）、蓬莱 Penglai（产学研联合研发、华为参与支持：IEEE S&P 2020 提出架构，OSDI 2021 发表可扩展内存保护 sPMP/SCCv2，支持数千 Enclave、512GB 安全内存）。

4.6 ARM CCA 与机密计算的安全等级

ARMv9 的 CCA（Confidential Compute Architecture）建立在 RME（Realm Management Extension）之上，把世界从 2 个扩展为 4 个安全状态：

Realm机密虚机/Realm VM新增：硬件隔离的机密执行环境，连 TEE、hypervisor 都不在其信任边界内

  • 关键机制：GPT 粒度保护表（以 4KB 粒度把物理内存划给四个状态，越界访问被硬件拒绝）；RMM（Realm Management Monitor）管理 Realm 的创建/运行/销毁，但按设计不属于 Realm 的 TCB（Realm 只信任硬件 + EL3 Monitor）；RMM 为 Realm 出具度量证明。

  • “安全等级”的三种理解：

    2. 方案隔离强度：TrustZone TEE（TCB 含整个 TEE OS）< SEV（有机密性无完整性）< SEV-SNP/TDX（+完整性+证明）< SGX（进程级、TCB 最小）≈ CCA Realm（VM 级、TCB 小）；

4.7 TEE 的攻击面与局限（实际场景应用）

  • TEE OS 本身的内存破坏漏洞可导致提权（QSEE、Trusty 历史上都有高危案例）；
  • 微架构侧信道：缓存/页表计时（CacheQuote、Page Cache 攻击）可窥探 TA 访存模式；瞬态执行攻击直接穿透 SGX；
  • 物理攻击：TEE 不承诺抗探针/故障注入，高价值密钥仍要 SE；
  • 防护方向：TEE OS 加固与模糊测试、恒定时间 TA、微码/硬件缓解（AEX-Notify 等）、TEE+SE 组合。
◆ 要点 三类方案的定位各不相同：TrustZone 靠世界隔离，是手机端主流；SGX 把信任边界缩到进程粒度，TCB 最小；SEV/TDX/CCA 面向云上机密虚机。无论哪一种，TEE 都不承诺防御侧信道与物理攻击，这一判断需要牢记。

5 处理器微架构安全：Meltdown 与 Spectre

5.1 预备知识：为什么缓存会泄密

  • 现代处理器为掩盖内存延迟，采用乱序执行 + 推测执行：按预测提前执行后续指令，预测错误时“回滚”架构状态（寄存器/内存），但微架构状态（缓存、分支预测器、缓冲区）不回滚。
  • 缓存命中（几周期）与未命中（几百周期）的时间差就是一条信息信道：攻击者通过“测某地址是否被 victim 带入缓存”逐位恢复秘密。
  • 三种经典缓存探测原语：
原语做法前提
Flush+Reloadclflush 清掉共享页某行 → victim 执行 → 重载该行测时：快 = victim 访问过与 victim 共享内存页
Prime+Probe先填满某组缓存 → victim 执行 → 重访测时：慢 = victim 用了该组无需共享内存（跨核可用）
Evict+Reload/Evict+Time用竞争代替 flush 的变体同上

5.2 Meltdown（2018，CVE-2017-5754）

  • 核心思想：乱序执行时，越权内存读取的数据已经在乱序窗口被取回并用于后续计算（把秘密字节编码进缓存），权限检查在指令“退休”时才生效——异常抛出后，缓存里的痕迹已经留下。
  • 攻击流程：读内核地址（必然触发权限异常）→ 异常前的乱序指令把该字节作为索引访问数组 → 异常处理完后用 Flush+Reload 找出“哪个槽变快”，由此恢复该字节。循环即可任意读内核内存（含 KASLR 布局、内核密钥）。
  • 缓解：KPTI（内核页表隔离，源于 KAISER）——用户态页表里几乎不映射内核空间，使攻击无地址可读；代价是系统调用切换开销。
  • 受影响面：Intel 广泛受影响；部分 ARM；AMD 因权限检查与数据访问并行化而基本免疫（注意对比三家方案）。

5.3 Spectre（2018，CVE-2017-5753 / 5715）

  • 核心思想：不越权读数据，而是诱骗推测执行“本来不会执行”的代码，让秘密数据经缓存编码泄露——利用的是分支预测器，所以“看起来合法的代码路径”成了攻击工具。论文结论：此类漏洞将长期存在。
  • v1 边界检查绕过（Bounds Check Bypass）：先训练分支为“合法”，再用恶意输入触发推测的越界读取/访问，把 array1[secret] 之类编码出去。缓解：编译器插推测屏障（x86 lfence、ARM CSDB/SB）、对索引掩码、恒定时间编码。
  • v2 分支目标注入（Branch Target Injection）：污染 BTB（分支目标缓冲器），让内核/其他进程推测地跳到攻击者选择的“gadget”（如 *(secret^base) >> ...）泄露数据。缓解：retpoline（编译器）、微码 IBRS/IBPB/STIBP、硬件 eIBRS、ARM 的 CSV2 特性位。
  • v4 推测存储绕过（SSB）：推测地忽略尚未就绪的 store，读到旧值。缓解：SSBD 微码开关。
  • 变体家族：SpectreRSB（返回栈缓冲器）、L1TF/Foreshadow（PTE present=0 时 L1D 残留数据被推测读取，直击 SGX 与虚机隔离）、MDS 家族（ZombieLoad/RIDL/Fallout：行填充缓冲/存储缓冲泄漏）、LVI（反向：向飞地内推测计算注入数据，需重编译缓解）、Downfall/ÆPIC 等。

5.5 相关但不同的内存攻击：Rowhammer

反复高频激活同一 DRAM 行，电荷泄漏导致相邻行位翻转：可把“只读”数据改写（提权）、翻转页表项、从 JS 沙箱发起（RAMBLEED 用于读；TRRespass 绕过 TRR 防护）。缓解：目标行刷新 TRR、提高刷新率、DDR5 的 ACT-RH 计数器、ECC（不彻底）。Rowhammer 属于故障注入类（内存扰动），不是瞬态执行攻击——两者容易混淆。

【硬件木马（Hardware Trojan）】 在芯片设计与制造阶段被植入的恶意电路，平时静默，被特定条件触发后执行恶意功能。
【硬件植入（Hardware Implant）】 在芯片出厂之后、通过物理接触（如物流拦截改装）附加或改装的硬件恶意组件，通常是分立器件/微小电路板。

6.2 硬件木马

6.2.1 结构与分类

6.3 硬件植入

  • 典型路径：物流拦截（interdiction）→ 开封加装微小器件（射频收发/篡改芯片）→ 复原封装。

  • 公开案例（注意事实争议）：

    1. The Big Hack（彭博商业周刊 2018 报道）：称间谍芯片被植入 Supermicro 服务器主板供应链；Apple/Amazon/Supermicro 均公开否认，至今无独立证据证实——常作为“供应链可信性讨论”的争议案例引用；
    2. Weeping Angel（维基解密 Vault7 披露）：对三星智能电视植入“伪关机窃听”固件；
    3. NSA ANT 目录：COTTONMOUTH 等 USB/网线级硬件植入工具系列；
    4. 欧洲议会 PEGA 委员会（2023）对执法机构“设备拦截”实践的质询引发广泛关注。
  • 木马 vs 植入的区别：木马在芯片内部、设计与制造阶段；植入是流片后的物理附加物；检测手段也不同（木马靠侧信道指纹/形式化，植入靠来料检验/X-Ray/拆解）。

6.4 固件与软件供应链

  • UEFI/固件 rootkit：LoJax（2018，首例野外 UEFI rootkit）、MoonBounce（2022）、BlackLotus（2023，利用被签名的漏洞组件绕过 Secure Boot）——固件持久化，重装系统无效；
  • 软件供应链：SolarWinds/Sunburst（2020，构建系统投毒）、XcodeGhost、CCleaner 事件——构建与分发环节是薄弱点；
  • 应对：固件签名 + 安全启动、SBOM/HBOM（软/硬件物料清单）+ VEX 漏洞通告、构建环境加固。

6.5 防护与保障体系

  • 技术：安全启动（限制植入/木马的生效条件）、芯片唯一 ID 与产线密钥注入（secure provisioning：密钥在 HSM 环境下注入，芯片与授权服务绑定，防克隆与掉包）、防篡改封装与签封、入库检验（X-Ray、声学、电测、抽样逆向）；
  • 管理：可信供应商认证与审计、可信代工（Trusted Foundry 思路）、全生命周期追溯；
  • 法规/框架：美国 EO 14028 与 NIST SP 800-161（C-SCRM）、EU Cyber Resilience Act；中国《关键信息基础设施安全保护条例》、GB/T 36637（ICT 供应链安全要求）等。
◆ 厂商实践与拓展 华为作为大型设备商，供应链安全治理覆盖供应商准入、产品安全基线、软件物料清单与漏洞响应（PSIRT）等环节；芯片侧通过唯一可信 ID、产线安全注入（HSM 环境烧录密钥）与全链安全启动保证“从硅片到服务”的可追溯与可验证。供应链安全的要点可以归纳为两条线：技术验证（安全启动/唯一 ID）与流程治理（供应商/物料清单）。

7 调试接口与系统级攻击（JTAG / UART）

7.1 JTAG

【JTAG】 IEEE 1149.1 边界扫描标准（1990），最初用于 PCB 互连测试，现泛指芯片的片上调试/烧写通道。5 根信号：TCK（时钟）、TMS（模式选择）、TDI/TDO（数据入/出）、TRST（复位，可选）。
  • 工作机制：TAP 控制器（16 状态状态机）在 IR 指令寄存器与DR 数据寄存器之间移位，访问片上调试逻辑（ARM 侧为 CoreSight DAP；简化两线版 SWD）；多芯片可串联（daisy-chain）。
  • 合法用途：互连/制造测试（BSDL 描述）、CPU 停核/单步/读写内存与寄存器/断点、烧写 Flash、FPGA 下载配置。

  • 攻击面：

    1. 量产设备调试口未锁时，攻击者可获得完全控制：停核后读全内存（提取密钥/生物模板）、直接改写 RAM 中的代码/数据、绕过或打补丁 bootloader、关闭安全标志位；
    2. dump 外部 Flash 固件后离线分析（binwalk），再回头利用；
    3. 扫描链攻击：进入测试模式读扫描链，可读出触发器状态（含运算中的密钥）——测试模式必须与产品模式隔离。

7.1.1 JTAG 防护

防护做法
熔断禁用量产时 eFuse 烧断调试口使能（最粗暴有效；注意与“抗毛刺可靠熔断”配套，防电压毛刺重开）
认证调试调试口保留但需挑战-响应认证（平台密钥签发授权），如 ARM ADAC（Authenticated Debug Access Control）
生命周期管理DEV → PROD → RMA 状态机：量产锁定，返修（RMA）时先擦密钥再授权调试
隔离/混淆调试引脚断线/复用、扫描链安全模式（测试态禁读机密触发器）
协议升级IEEE 1149.7（两线 cJTAG）等新标准自带安全特性

7.2 UART 调试口

  • 特征：TX/RX/GND 三线（常见 115200 8N1），成本极低；PCB 上常是 4 针排（VCC/TX/RX/GND），万用表通断 + 逻辑分析仪即可定位。

  • 攻击方案：

    1. 读启动日志，了解 bootloader 与内核配置，发现调试后门；
    2. 在 U-Boot autoboot 倒计时内按键打断，即可进入 U-Boot 命令行：printenv/setenv 改 bootargs（如 init=/bin/sh 直接拿 root shell）、tftpboot 加载任意内核、修改/擦除环境变量（可能关掉安全启动开关）；
    3. Linux 控制台未设认证时，可直接拿到 root shell（路由器/机顶盒/IoT 常见）。
  • 防护：量产关闭串口控制台（quiet/loglevel=0）、U-Boot 设密码/锁定 autoboot 打断、裁剪可执行命令集（只留只读诊断）、串口认证。

7.3.1 IoT/嵌入式设备攻击方法论（系统级视角）

  1. 拆解观察：找调试口（4 针排、丝印 TX/RX/JTAG 焊盘）、 Flash 型号；
  2. UART/JTAG 尝试：波特率扫描、JTAGulator 定位；
  3. dump 固件（调试口或 Flash 夹具）→ binwalk 分析（文件系统、密钥、硬编码口令）；
  4. 静态/动态分析找漏洞；
  5. 利用：改 bootargs、刷固件、毛刺绕验签；
  6. 持久化/横向（若是渗透场景）。

7.4 底软漏洞挖掘（固件与底层软件安全）

“底软”指 BootROM、bootloader、UEFI、BMC、内核与驱动、RTOS、基带等底层软件，其漏洞原理与挖掘技术是硬件安全工作的重要组成部分。

7.4.1 底层软件攻击面

攻击面典型问题

UEFI / SMMSMM callout（SMM 内调用普通世界内存的函数）、指向 SMRAM 的 DMA、变量服务溢出、固件卷（FV）解析漏洞

7.4.3 漏洞缓解与安全开发（记忆清单）

  • 运行时缓解：ASLR、DEP/NX、Stack Canary、CFI、glibc safe-linking；这些缓解在底软环境中往往缺省关闭，未开启本身就是最大的问题来源。
  • 硬件缓解：ARM PAC/BTI/MTE、x86 CET（对照表见第 5 章）、IOMMU（堵 DMA 攻击）、SMM 加固（SMRAM 锁定 + DMA 保护）。
  • 流程与工具：sanitizers（ASAN/UBSAN/KASAN）进 CI、覆盖率门限、OSS-Fuzz 式持续模糊、CERT C/MISRA 安全编码、CVE 情报监控、固件全链签名 + 防降级。
◆ 要点 分析底软安全问题时，可以按这样的顺序展开：先盘点攻击面，再归类漏洞原理，然后选择挖掘手段（仿真、模糊测试、符号执行），最后说明缓解措施如何进入开发流程。其中 TEE TA 的模糊测试、Double-fetch、DMA 与 IOMMU 三个话题最能体现实际理解。
◆ 要点 按“接口 → 能力”的对应关系记忆：JTAG = 芯片级完全控制（读写内存/改代码）；UART = 系统 shell/bootargs 级控制；SPI Flash = 固件级（dump/篡改）。防护共同原则：调试口生命周期管理 + 全链安全启动 + 固件签名加密。
◆ 厂商实践与拓展 华为终端的安全启动链（BootROM → Bootloader → 内核 → 系统逐级验签、验签密钥与哈希存于独立安全区域）正是对上述攻击面的系统性回应；鲲鹏服务器同样支持 UEFI Secure Boot 与 TPM 度量。HarmonyOS 设备的调试端口按生命周期状态管理，量产态默认关闭。

8 工业硬件安全实践专题

《华为算力基础设施安全技术白皮书——端管云协同》给出的主线是：以硬件可信根为起点，使能安全启动与可信启动，确保只有授权且经密码学校验的代码可执行；运行时以 TEE/机密计算保护敏感数据，密码体系内生国密。本章按“端—管—云”梳理华为的硬件安全版图，均为公开资料。

8.1 终端侧：麒麟芯片与 HarmonyOS

  • inSE 集成安全单元：2016 年起华为旗舰机型集成金融级 inSE（通过金融行业认证），承载 Huawei Pay、eID（公民网络电子身份）等高价值密钥；HarmonyOS NEXT 安全白皮书将 SE（安全单元）与 TEE 并列为“软硬结合双重防护”的支柱，SE 负责芯片级物理防护。

  • 安全启动链：BootROM → Bootloader → 内核逐级验签，验签密钥与哈希存储于与主 CPU 隔离的安全区域；配套防回滚与密钥防回退。

9.5 垂直行业主流方案

9.5.1 汽车电子

  • 车内安全模块分级：HIS SHE（Secure Hardware Extension：MCU 内置 AES-128 安全模块，最普及）→ EVITA Full/Medium/Light HSM（欧盟项目定义的车载 HSM 分级）→ ASIL 相关安全岛；软件栈为 AUTOSAR CSM/CryIf；V2X 另需专用 HSM。
  • 法规：ISO/SAE 21434（网络安全工程）+ UNECE R155（CSMS 车企管理体系，新车型准入强制）+ R156（软件更新管理）。
  • 经典案例：2015 年 Jeep Cherokee 远程控制（Miller & Valasek，召回 140 万辆，催生整个车联网安全行业）；Megamos Crypto 防盗转发器被破解（2013，公开研究甚至遭厂商诉讼）；无钥匙进入中继攻击（relay attack）至今仍是车险诈骗主力。

9.5.2 支付与金融

  • 卡与终端：EMV 标准体系（PBOC 为国内对应），POS 终端认证 PCI PTS（安全要求 + 渗透测试），卡片/终端安全评估走 EMVCo。
  • 主流金融 HSM 厂商：Thales（Luna/PayShield）、Utimaco、Entrust nShield——银行 PIN/密钥体系与 CA 根密钥的行业标准配置。
  • 支付令牌化：Apple Pay/Google Pay 以设备令牌替代 PAN，密钥在 SE/TEE 内，业界与华为 inSE 方案同构。

9.5.3 IoT 与嵌入式

  • 安全元件选型：Microchip ATECC608、NXP SE050、ST STSAFE 等（预认证 SE，密钥托管/椭圆曲线运算）；eSIM + GSMA RSP 远程配置逐步替代插拔 SIM。
  • 固件底座：MCUboot（安全启动/升级）+ TF-M（Cortex-M TEE）+ PSA Certified 认证。
  • 资源受限设备的密码：NIST 2023 年选定 Ascon 为轻量级密码标准（SP 800-232）。

9.5.4 身份与在线认证

  • FIDO2/WebAuthn + CTAP：免密登录，硬件安全密钥（YubiKey、Google Titan Key）内置 SE 承载私钥；Google Titan Key 2021 年因蓝牙配对密码学缺陷召回——硬件供应链中的密码学审计同样不可少。
  • ePassport（ICAO：BAC/PACE 协议）、各国 eID 与手机 eID（华为 inSE 方案第 8 章）。

9.7 面向 AI 算力的硬件安全

AI 算力体系的关键资产是模型权重与训练、推理数据，架构特点是 GPU/NPU 加 HBM、高速互连与 chiplet。可信根、隔离、加密这三类既有技术需要逐一延伸到这套新架构上：

主题要点
威胁模型云内多租户互窃（共享 GPU 的微架构侧信道与数据残留）、恶意云管理员、物理/近场攻击；保护资产：模型权重（商业核心机密）、提示词与训练数据（隐私）、模型完整性（防后门/篡改）
加速器可信基NPU/GPU 安全启动与固件度量（昇腾、NVIDIA 数据中心 GPU 均内置 RoT）；GPU Confidential Computing：显存/HBM 加密 + 完整性 + 远程证明（H100 起，见本章 9.3）
多租户隔离硬件切分（NVIDIA MIG）+ 上下文切换时的缓存/共享 SRAM 清理；L2 与共享内存残留是 GPU 侧信道的主要来源
互连与封装安全chiplet 与 UCIe、NVLink 与 NVSwitch、CXL 的加密与认证（CXL 信任域互连标准化推进中）——算力扩展到哪里，信任边界就要跟到哪里
模型供应链模型文件签名/哈希校验、权重在 TEE 内运行时解密、反序列化投毒（pickle 类漏洞）、模型水印/指纹做泄露溯源
隐私计算与 AI 结合FHE 密态推理（CKKS 路线）、联邦学习 + TEE 聚合 + DP 噪声（与第 1 章 FHE 与隐私计算一节呼应）
AI 辅助安全研究LLM 辅助代码审计与 harness 生成、机器学习侧信道分析（ASCAD 数据集，见第 11 章），覆盖“用 AI 做安全”与“保护 AI 本身”两个方向
◆ 要点 概括地说，AI 算力安全是把可信根、隔离、加密这三类技术延伸到 GPU/NPU、HBM 与互连链路上，再以隐私计算保护数据本身。MIG、CXL 安全、模型水印这些具体点，最能反映理解的深度。

9.8 安全 IP 与芯片生态

  • SE 主流厂商：NXP、Infineon、STMicroelectronics、Microchip——手机 eSE/银行卡/eSIM 芯片的主要来源。
  • 安全 IP 供应商：Rambus（CryptoManager RoT，并购 Silex Insight）、Synopsys（DesignWare Security IP，并购 PUF 厂商 Intrinsic ID）、Cadence、Secure-IC 等，提供 TRNG/PUF/安全启动/RoT 子系统等可认证 IP。
  • 自研芯片平台的关键决策：“买认证 IP 还是自研 RoT”——认证（CC/商密）通常绑定已验证 IP，自研则需自证安全性与评估成本。
  • FPGA/MCU 的安全启动：Xilinx Versal/Zynq（前车之鉴 Starbleed）、STM32 读保护（RDP）、Nordic/NXP 的 TF-M 集成。
◆ 要点 本章可以作为概念与实例的对照材料。各方案的定位可以用一句话概括：Apple SEP 保护生物特征，Titan M2 源自开源 OpenTitan，Pluton 是微软定义的 CPU 内安全处理器，Knox Vault 是独立抗拆芯片，Nitro 是云服务器的硬件可信根，Caliptra 是数据中心芯片内 RoT 规范。

10 标准、认证与评估体系

硬件安全的特殊性在于：安全性无法靠“自查”取信于第三方，必须通过标准化评估认证。对工程师而言，标准是产品市场准入的门票，也是体系化知识的最好大纲；“标准—机构—等级”的对应关系适合整理成速查表。

10.1 通用安全评估：Common Criteria（ISO/IEC 15408）

  • 结构：PP 保护轮廓（一类产品的安全需求模板）→ ST 安全目标（具体产品声明）→ TOE 评估对象；评估保证级 EAL1–EAL7（功能测试 → 方法论设计与测试 → 方法论设计/测试与彻底验证）。
  • 智能卡/SE/安全芯片惯例：EAL4+（增强）/EAL5+/EAL6+，关键在漏洞分析深度 AVA_VAN（.1 至 .5，.5 对应高攻击潜力攻击者，EAL5+/6+ 智能卡认证普遍标注 AVA_VAN.5）——“EAL 几”要与 AVA_VAN 深度一起看。
  • 互认：CCRA 与 SOG-IS 互认协议（欧洲安全评估互认，智能卡主流）。
  • 主要评估机构：SGS Brightsight、Riscure、UL、TÜV、Applus 等；国内由中国网络安全审查认证和市场监管大数据中心（原 CCRC）与指定测评实验室承担。

10.6 测评实操要点

除了懂标准（本章前文），还需要了解测评的具体做法：

  • TRNG/随机数评估：NIST SP 800-90B（熵源估计 + 在线健康测试：重复计数测试/自适应比例测试）、SP 800-22 统计测试套件、德国 BSI AIS-31（PTG.2/PTG.3 类）；送检需提交熵源设计说明与健康测试实现——“熵源 + 健康测试 + DRBG 构造”三层都要证据。
  • 侧信道评估流程：表征（characterization，定位泄漏点）→ TVLA 泄漏评估（固定 vs 随机 Welch t 检验；一阶对应无掩码/一阶掩码，高阶掩码要配高阶测试）→ 攻击验证（CPA 实际恢复密钥）；关注采样规模与置信度。
  • 故障注入评估：参数空间扫描（电压/时钟/电磁/激光位置与能量），定义目标函数（跳过校验、翻转目标比特），统计成功率与可重复性；验证防护响应（传感器报警、密钥清零、状态机 fail-closed）。
  • 算法符合性测试：KAT 已知答案测试（CAVP 与商密检测中心同源思路）、边界与异常输入、密码协议互操作测试。
  • 送检流程：送样 → 方案/文档评审 → 测试执行 → 问题整改 → 报告 → 认证证书；研发侧应先做“预扫描”（pre-compliance），用 ChipWhisperer 自测（机构级用 Riscure Inspector，见第 11 章工具表）。
